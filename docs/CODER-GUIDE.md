# คู่มือการใช้งาน DRG Optimizer สำหรับ Coder และทีมเวชสถิติ

เอกสารนี้จัดทำขึ้นสำหรับ Coder (ผู้ให้รหัสโรคและหัตถการ) และทีมเวชระเบียน/เวชสถิติ โรงพยาบาลกันทรลักษ์ เพื่อทำความเข้าใจการทำงาน กฎเกณฑ์ความปลอดภัย และขั้นตอนการนำข้อเสนอแนะไปใช้จริง

---

## 1. จุดประสงค์ของระบบ

DRG Optimizer พัฒนาขึ้นเพื่อช่วยทบทวนและค้นหารหัสการวินิจฉัยหลัก (PDx), การวินิจฉัยร่วม (SDx) หรือหัตถการ (Proc) ที่สอดคล้องกับหลักฐานการรักษาจริงในประวัติผู้ป่วย (เช่น รายการยา, เหตุผลการใช้ยาปฏิชีวนะ/ยาควบคุมเฉพาะ) ซึ่งอาจส่งผลให้กลุ่มวินิจฉัยโรคร่วม (DRG) และค่าน้ำหนักสัมพัทธ์ปรับตามวันนอน (AdjRW) สะท้อนความรุนแรงของโรคและการใช้ทรัพยากรที่แท้จริงของโรงพยาบาลได้ดียิ่งขึ้น

> [!IMPORTANT]
> **ระบบนี้เป็นเพียง "เครื่องมือช่วยแนะนำและคำนวณ" (Decision Support)**
> ทุกข้อเสนอแนะจะต้องได้รับการตรวจสอบเอกสารเวชระเบียน (Medical Record) และยืนยันโดย Coder ก่อนนำไปแก้ไขในระบบ HOSxP เสมอ **ห้ามเปลี่ยนรหัสโดยไม่มีหลักฐานทางการแพทย์กำกับโดยเด็ดขาด**

---

## 2. วิธีการอ่านและตีความ Suggestions

เมื่อกรอก AN และกดปุ่ม **"โหลดเคสและวิเคราะห์"** ระบบจะแสดง:

### 2.1 Baseline Case (ข้อมูลเดิม)
- รหัส PDx, SDx 1–4, Proc 1–3 เดิมที่มีการบันทึกไว้ในฐานข้อมูล
- ค่า DRG เดิม, AdjRW เดิม และประมาณการชดเชยตาม Base Rate ของโรงพยาบาล

### 2.2 Evidence Candidates (รหัสที่พบหลักฐาน)
- รหัส ICD-10 ที่ระบบดึงมาจาก:
  1. `presc_reason`: เหตุผลการสั่งใช้ยา (เช่น ในตาราง `ovst_presc_ned`)
  2. `need_order_reason`: เหตุผลความจำเป็นในการสั่งยา/เวชภัณฑ์ใน `opitemrece`
- มีปุ่มลิงก์ไปยังคลังข้อมูลมาตรฐานของกระทรวงสาธารณสุข (`/libs/icd10/{code}`) เพื่อตรวจสอบชื่อโรคภาษาไทย/อังกฤษ

### 2.3 ตารางจัดอันดับข้อเสนอแนะ (Ranked Recommendations)
ตารางจะเรียงลำดับจากค่า **ΔAdjRW (ส่วนต่าง AdjRW ที่เพิ่มขึ้น) จากมากไปหาน้อย**:
1. **รูปแบบข้อเสนอแนะ**:
   - `สลับเป็น PDx (Swap PDx)`: ลองนำรหัสที่มีหลักฐานขึ้นเป็นวินิจฉัยหลัก และปรับรหัสเดิมเป็นวินิจฉัยร่วม
   - `เพิ่ม SDx (Add SDx)`: เติมรหัสที่มีหลักฐานเป็นวินิจฉัยร่วมเพิ่มเติม
2. **DRG ใหม่ & AdjRW ใหม่**: ผลลัพธ์จากการเรียก Grouper ทางการของ สปสช./กระทรวงสาธารณสุข (Version 6 TGrp6305)
3. **หลักฐานประกอบ (Evidence)**: แสดงรายการยาและข้อความเหตุผลที่แพทย์หรือเภสัชกรบันทึกไว้ในระบบ

## 3. กฎเหล็กด้านความถูกต้องทางการแพทย์ (Clinical Coding Safety)

1. **Rule of Evidence (หลักเกณฑ์หลักฐานเชิงประจักษ์)**:
   - มีการสั่งใช้ยา Meropenem พร้อมระบุเหตุผลว่า `Severe sepsis A41.9` แต่ในชาร์ตผู้ป่วยแพทย์ได้สรุป Sepsis ไว้หรือไม่? มีผลเพาะเชื้อยืนยันหรือไม่? มีเกณฑ์ SIRS / SOFA score หรือไม่?
   - หากมีหลักฐานในเวชระเบียนชัดเจน Coder จึงจะสามารถสรุปและบันทึกรหัสเพิ่มได้
2. **ห้าม Upcoding โดยปราศจากข้อบ่งชี้**:
   - ห้ามลงรหัสที่ให้ค่า DRG สูงขึ้นเพียงเพราะระบบแนะนำ หากไม่มีการวินิจฉัยหรือการดูแลรักษาจริงในผู้ป่วยรายนั้น
3. **Read-Only Guarantee**:
   - ตัวแอปพลิเคชันไม่ทำการบันทึก (INSERT/UPDATE/DELETE) ลงในฐานข้อมูล HIS/HOSxP ใดๆ ทั้งสิ้น
   - การแก้ไขรหัสต้องทำผ่านกระบวนการปกติในโปรแกรม HOSxP โดยผู้มีสิทธิ์เท่านั้น

## 4. ตารางแปลงรหัสสถานะจำหน่าย (Discharge Status Mapping)

ระบบรับค่า `dchtype` และ `dchstts` จากตาราง `ipt` ใน HOSxP แล้วแปลงเป็น `dcCode` 2 หลักสำหรับส่งเข้า Grouper:

| dchtype (IPT) | dchstts (IPT) | รหัส Grouper (dischs + discht) | ความหมาย |
| :--- | :--- | :--- | :--- |
| `1` (With Approval) | `1` (Complete Recovery) | `11` | จำหน่ายโดยแพทย์อนุญาต (หายดี) |
| `1` (With Approval) | `2` (Improved) | `12` | จำหน่ายโดยแพทย์อนุญาต (อาการดีขึ้น) |
| `1` (With Approval) | `3` (Not Improved) | `13` | จำหน่ายโดยแพทย์อนุญาต (ไม่ดีขึ้น) |
| `2` (Against Advice) | `*` | `21` | ขอกลับบ้านเอง / ปฏิเสธการรักษา |
| `3` (Escape) | `*` | `31` | หลบหนี |
| `4` (Refer) | `*` | `41` | ส่งต่อสถานพยาบาลอื่น |
| `5` (Dead) | `*` | `51` | เสียชีวิต |

*หมายเหตุ: หากข้อมูลในตาราง `ipt` เป็นค่าว่าง ระบบจะใช้ค่าปริยายปลอดภัยคือ `11` (Discharged with approval, improved)*

## 5. ค่าตั้งต้นที่ใช้แทนข้อมูลที่ขาดหาย (Transparency Disclosures)

ในตาราง `CaseDetail` ปัจจุบันยังไม่มีข้อมูลบางส่วนที่ Grouper นำไปใช้คำนวณ ระบบจึงแสดงผลและใช้ค่ามาตรฐานอย่างเปิดเผยดังนี้:
- **น้ำหนัก (weight)**: กำหนดเป็น `0 kg` (สำหรับผู้ใหญ่ทั่วไป)
  *ข้อควรระวัง: สำหรับเคสทารกแรกเกิด (Newborn/Neonatal) น้ำหนักแรกรับมีผลอย่างยิ่งต่อ DRG ควรนำเคสไปตรวจสอบผ่าน Grouper เต็มรูปแบบอีกครั้ง*
- **อายุวัน (age_day)**: กำหนดเป็น `0 วัน`
- **ระยะเวลานอนชั่วโมง (los_hour)**: กำหนดเป็น `0 ชั่วโมง`
- **Base Rate**: กำหนดค่าเริ่มต้นไว้ที่ `8,350 บาท` (สามารถปรับแก้ตามประกาศอัตราจ่ายจริงของ สปสช. ได้ในหน้าจอ)
